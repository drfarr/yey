# nap

**Paste anything. Find out what you could have slept through.**

nap reads the email, the 47-reply Slack thread, the "quick sync" notes, the terms of service, and gives you back:

- a **nap score** (0 to 100): how much of it was filler
- a one-line **verdict** you'll want to screenshot
- the **tl;dr** in one sentence
- up to three **need to know** bullets
- the single thing you have to **do**
- a share link with a generated **card image**, so posted links look like the card, not a wall of text

Built on Claude (`claude-opus-5-5`) with structured outputs, so the response is always the same shape.

## Deploy to Vercel

1. Import this repo in Vercel and set the **Root Directory** to `nap`. The framework preset is "Other".
2. Add the **Upstash Redis** integration from the Vercel Marketplace (Storage tab). It sets the `UPSTASH_REDIS_REST_*` or `KV_REST_API_*` variables nap looks for. Without it, share links and rate limits live in process memory and reset on cold starts.
3. Set `ANTHROPIC_API_KEY` in the project's environment variables.
4. Deploy. Turn on **Web Analytics** in the project settings if you want page views; the script tag is already in the page.

Or from the command line:

```bash
cd nap
npx vercel link
npx vercel env add ANTHROPIC_API_KEY
npx vercel --prod
```

What runs where:

| Route           | Runtime         | File             |
| --------------- | --------------- | ---------------- |
| `/`             | static          | `public/index.html`, generated by `npm run build` from `src/index.html` |
| `POST /api/nap` | Node, 60s max   | `api/nap.ts`     |
| `GET /api/nap/:id` | Node         | `api/nap/[id].ts` |
| `GET /n/:id`    | Node, rewritten | `api/n/[id].ts`  |
| `GET /api/og?id=` | Edge          | `api/og.ts`, renders the 1200x630 card with `@vercel/og` |

## Run locally

```bash
cd nap
npm install
cp .env.example .env     # fill in ANTHROPIC_API_KEY, or use `ant auth login`
npm run dev              # http://localhost:3000
```

The dev server in `src/server.ts` serves the same routes as the Vercel functions, including the card image, with an in-memory store.

Pipe things at it from the terminal:

```bash
pbpaste | npm run nap
npm run nap -- that-email.txt
npm run nap -- that-email.txt --json
```

## API

```
POST /api/nap        {"text": "..."}   ->  { id, url, image, tldr, needToKnow, action, napScore, verdict, stats, share }
GET  /api/nap/:id                      ->  same, by id
GET  /n/:id                            ->  shareable HTML card with og: tags
GET  /api/og?id=:id                    ->  PNG card (no id: the generic nap card)
```

## Limits and privacy

- 40 to 60,000 characters per nap.
- Per IP: 10 naps a minute and 40 a day by default. Tune with `NAP_LIMIT_PER_MINUTE` and `NAP_LIMIT_PER_DAY`.
- The pasted text is never stored. Only the result is kept, behind the share id, for 30 days.
- Refusals from the model are surfaced as a 422 with a friendly message.

## Cost

One nap is roughly 1,000 input tokens and 300 output tokens on Claude Opus 5.5, around a cent. The system prompt is cached. The daily cap keeps a single abuser under about 40 cents a day.

## Tests

```bash
npm run check     # typecheck, tests, build
```

The model is mocked in tests, so no API key is needed. The card renderer runs for real and is checked for a valid PNG.

## Why it spreads

The output is the marketing. Every nap ends in a number and a one-liner that are more fun to post than the original text was to read. The share page and the card image send the next person back to paste their own.
